# Specification change log

Changes to the Assignment 01 specification made during Assignment 02. Each entry gives the reason and the affected identifiers.

| # | Date | Change | Rationale | Affected IDs |
|---|------|--------|-----------|--------------|
| 1 | 2026-10-31 | Audio library changed from `react-native-track-player` to `expo-audio` (playlist, background playback, lock-screen controls with next and previous). | `react-native-track-player` has had no stable release since August 2025 and is not maintained for Expo SDK 58 and React Native 0.88. `expo-audio` is maintained with the SDK and provides the required features. The required permissions are unchanged. | CMP-APP-03, table 5.5 (Audio), SD-01 |
| 2 | 2026-10-31 | `game_questions` gains the columns `answered` and `clip_start_sec`. | `answered_mood` is null both before an answer and after a timeout, so a separate flag is needed to reject a second answer (409); the clip start is stored so that the same clip is played if a round is resumed. | ENT-10, API-11, API-12 |
| 3 | 2026-10-31 | Songs played in the last two hours are moved to the end of the list on the device. | The data model has no play history table; the device already stores the last played songs (AC-10.1.5), so no personal listening history is sent to the server (NFR-PRIV-01). | AC-06.1.3, CMP-APP-06 |
| 4 | 2026-10-31 | Only the development Supabase project is created at this stage; the demonstration project will be created before the final submission. | The free plan allows two active projects per organisation and one slot is already in use. | Section 5.10 |
| 5 | 2026-11-13 | Game changed from Mood Guess (guessing plurality community mood) to Artist Guess (guessing the song's `artist_name` from 4 options); simplified post-answer feedback without mood distribution or quick-tag button. | Community mood tags are subjective and can tie or skew, whereas `artist_name` is an objective ground truth available on all songs in the catalogue without requiring >= 5 tags per song. | FR-11, UC-10, ENT-10, API-11, API-12, SCR-13, SCR-14 |
| 6 | 2026-11-13 | Dropped the Game module (`game_rounds`, `game_questions`, `SCR-13`, `SCR-14`) and replaced it with two new modules: (1) Song Sharing via native Share Sheet (Facebook & other apps) from Now Playing and Song Info, and (2) Pomodoro Focus + Music mode (`pomodoro_sessions`, `Focus` tab) with presets (`25/5`, `50/10`) and custom durations (`5–120` min focus, `1–30` min break), auto-play mood mix, and auto-pause on break. | Aligns the second service with study/entertainment usage without requiring saved playlists (only an ephemeral playback queue exists) or game-question seeding constraints. | FR-11, FR-12, UC-10, ENT-09, API-11, API-12, SCR-07, SCR-13, SCR-16 |
| 7 | 2026-11-15 | Pomodoro transitions are applied in the store services and checked on every player status event and on return to the foreground, not only by the Focus screen's timer. Shared links point to the Jamendo track page instead of the MP3 stream. "Today" in the focus statistics starts at the listener's local midnight, sent by the application as `todayStart` (API-11 body, API-12 query). Sessions that cannot be sent while offline are counted on the device for the same day. `VIBRATE` is added to the install-time permissions. | The screen timer stops in the background, so music kept playing after Focus ended with the screen off (AC-12.1.3). An MP3 link shows no title or artwork on Facebook. A UTC day put sessions from 0:00 to 7:00 in Vietnam on the previous day. Android ignores `Vibration.vibrate` without the `VIBRATE` permission, and `app.json` lists the permissions explicitly. | AC-11.1.1, AC-12.1.3, AC-12.1.4, API-11, API-12, CMP-APP-11, NFR-PERM-01 |
| 8 | 2026-11-15 | Completed focus sessions are queued on the device (persisted, with a UUID generated on the device) and resent on reconnection, foreground and sign-in; API-11 takes `id` and `completedAt` and ignores an `id` it already stored. `docs/openapi.yaml` and a Postman collection are added. The Edge Function validators are tested with Jest instead of Deno test. FR-13 rank movement, FR-14 mood statistics and FR-18 search filter by mood are implemented. The unused game error codes `ALREADY_ANSWERED` and `NOT_ENOUGH_SONGS` are removed. | A session completed offline never reached the server, and a plain retry of a POST could record it twice. The specification referred to an OpenAPI file that did not exist. The validators have no Deno-specific imports, so the existing Jest run covers them. | UC-10, AC-12.1.4, NFR-NET-01, NFR-OFF-03, API-11, SD-04, FR-13, FR-14, FR-18, table 5.5 |
| 9 | 2026-11-17 | Row-level security no longer lets users insert, update or delete `mood_tags`, or insert `pomodoro_sessions`, directly; these writes go only through the Edge Function (API-07, API-08, API-11). Ending a session for any reason (Sign out, a refresh token the server rejects, or no session at start-up) now clears the personal data on the device. The tag sheet and Now Playing load the listener's own tags of the current song, and Profile counts all tags, not only the 90 days of the diary. | The write policies let any client with the publishable key bypass the rate limit and the server checks. Only Sign out cleared the device, so after an expired session the next account inherited the queue and sent the previous account's pending tags and focus sessions. A tag older than the diary window showed as off, and tapping it sent a PUT that erased its note. | Table 6.2, NFR-SEC-04, NFR-SEC-05, AC-01.2.2, AC-04.1.4, SCR-09, SCR-16 |
